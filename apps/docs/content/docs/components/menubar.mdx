title: Menubar
description: A row of menus across the top of an application, like the File, Edit and View of a desktop program.
---

Use a menubar in something that works like a desktop application: an editor, a design tool, a spreadsheet. It holds every command the application has, grouped under a few names. For a single list of actions on one thing, use a [dropdown menu](/docs/components/dropdown-menu). For links between the pages of a site, use a [navigation menu](/docs/components/navigation-menu).

## Install

```sh
pnpm add @nuvui/react
```

## Import

```tsx
import {
  Menubar,
  MenubarContent,
  MenubarItem,
  MenubarMenu,
  MenubarSeparator,
  MenubarShortcut,
  MenubarTrigger,
} from "@nuvui/react";
```

The styles come from `@nuvui/react/styles.css`, which you load once for the whole app. [Getting started](/docs) covers that, and how to load only this component's CSS.

## Parts

| Part | What it is |
| --- | --- |
| `Menubar` | The bar. It holds which menu is open. |
| `MenubarMenu` | One menu: its entry in the bar and its panel. Renders nothing itself. |
| `MenubarTrigger` | The entry in the bar that opens the menu. |
| `MenubarContent` | The panel with the items. |
| `MenubarItem` | One command. |
| `MenubarCheckboxItem` | An item that's on or off. |
| `MenubarRadioGroup` | Wraps radio items and holds which one is chosen. |
| `MenubarRadioItem` | One choice in a radio group. |
| `MenubarLabel` | A heading for the items under it. It can't be focused. |
| `MenubarSeparator` | A line between groups of items. |
| `MenubarShortcut` | The keys that do the same as an item, shown at the end of its row. |
| `MenubarGroup` | Groups items for screen readers. It has no look of its own. |
| `MenubarSub` | Holds the open state of a submenu. |
| `MenubarSubTrigger` | The item that opens the submenu. |
| `MenubarSubContent` | The submenu's panel. |

These are separate exports, not properties of `Menubar`. `Menubar.Menu` isn't available, because property access on a client component doesn't work from a server component.

What goes inside a menu is the same as in a [dropdown menu](/docs/components/dropdown-menu), part for part.

## Shortcuts

`MenubarShortcut` shows the keys that do the same thing as an item. It only shows them: listening for the keys is your code's job.

It's hidden from screen readers, because its text would otherwise run into the item's name. To have the keys announced, put them in `aria-keyshortcuts` on the item, as the first example does. That attribute has its own way of writing keys: `Control+N`, not `Ctrl+N`.

## Moving between menus

A click on an entry opens its menu. From then on, moving the pointer to another entry opens that one and closes the first, with no click, until a menu is closed again. The arrow keys do the same from inside a menu.

A menu here closes at once, with no fade. A menu that's fading out is still on the page, and Radix would then take focus arriving in the next menu for a click outside the old one and close them both.

## On small screens

A menubar belongs to wide screens and a pointer. On a phone the entries are 44 pixels tall, and a bar with more entries than fit wraps onto a second line, so it still works. But a row of menus is a poor fit for a narrow screen. Consider putting the same commands in a [sheet](/docs/components/sheet) there.

## Accessibility

### Keyboard

| Key | What it does |
| --- | --- |
| <kbd>Tab</kbd> | Moves focus into the bar, to the entry that last had it. Pressed again, it leaves the bar. |
| <kbd>→</kbd> and <kbd>←</kbd> | On the bar, move to the next or previous entry. Inside a menu, close it and open the one beside it. |
| <kbd>Enter</kbd>, <kbd>Space</kbd> or <kbd>↓</kbd> | On an entry, opens its menu and moves focus to the first item. |
| <kbd>↓</kbd> and <kbd>↑</kbd> | Move to the next or previous item. Disabled items are skipped. |
| <kbd>Home</kbd> and <kbd>End</kbd> | Move to the first or last item. |
| A letter | Moves to the next item that starts with it. |
| <kbd>Enter</kbd> or <kbd>Space</kbd> | Chooses the focused item. |
| <kbd>→</kbd> | On a submenu's trigger, opens the submenu. |
| <kbd>←</kbd> | Inside a submenu, closes it and goes back to its trigger. |
| <kbd>Esc</kbd> | Closes the menu and returns focus to its entry. |

When <kbd>→</kbd> or <kbd>←</kbd> opens the menu beside the one you were in, focus lands on the menu and not on its first item. <kbd>↓</kbd> goes to the first item from there. That's how Radix does it.

### What the component handles

Most of this is Radix. The library doesn't change it.

- The bar has `role="menubar"`. Its entries are `menuitem`s with `aria-haspopup="menu"` and `aria-expanded`, and each panel is a `menu` named by its entry.
- The bar is one stop in the tab order. The arrow keys move inside it and skip a disabled entry.
- The menus aren't modal: the rest of the page stays reachable while one is open, and a click anywhere else closes it.
- An entry with keyboard focus has a ring. The row that has focus inside a menu is filled with the primary color, which has at least 3:1 contrast with the panel.
- Where the browser forces its own colors, as Windows high contrast does, the fill isn't drawn. The focused row has an outline there instead.
- Entries are 44 pixels tall on a touch screen and 32 with a mouse, and so are the rows.
- A menu only fades in when the visitor hasn't asked for reduced motion.

### What you need to handle

- Name the bar with `aria-label`, such as "Document". A page can then have more than one and a screen reader can tell them apart.
- Listen for the shortcuts you show. `MenubarShortcut` is only text.
- Keep the entries to a word each, and the same from one screen to the next. People learn where a command lives.
- In a right-to-left layout, pass `dir="rtl"`.

## CSS variables

The bar and its menus have separate variables, because they're separate things on the page. Set the bar's on `Menubar` or anything around it.

```css
.editor {
  --nuv-menubar-bg: transparent;
  --nuv-menubar-border: transparent;
}
```

The menus render at the end of `<body>`, so set theirs on `:root` or `body`, or straight on `MenubarContent` with `style` or a class.

## Server components

The menubar parts are client components. They carry `"use client"`, and the build checks that the directive is still there in the published files.

You can put a menubar together inside a server component, as the first example on this page does. An `onSelect` handler is the usual reason to need a client component of your own.

## Themed sections

A menu opened from a bar inside a `data-theme="dark"` section doesn't inherit that theme, because it isn't rendered inside the section. Pass the section's element as `container` to `MenubarContent`, and to `MenubarSubContent` if there is one.

## Do and don't

**Do**

- Use the names people know from other programs: File, Edit, View, Help.
- Leave an unavailable command in place and disable it, so the menus don't change shape.
- Show a shortcut next to every command that has one.

**Don't**

- Don't use a menubar for links between the pages of a site.
- Don't put a single command straight in the bar. Every entry opens a menu.
- Don't hide a screen's main action in a menu. Give it a button as well.
