Use a password input wherever someone types a password or another secret. The button lets people check what they typed before they send it, which matters most on a phone keyboard.

## Choosing a new password

Set `autoComplete="new-password"` where someone is making a password up. It tells the browser and password managers that this isn't the place for the saved one.

## What it does by itself

Most of this is Radix. The library doesn't change it.

- The password is hidden again when the form it's in is submitted or reset, so it isn't left readable on a screen someone walks away from.
- After a click on the button, the cursor goes back into the input, where it was. Pressed from the keyboard, focus stays on the button so it can be pressed again.
- Autocapitalize and spell checking are off, so a phone keyboard doesn't change what's typed.
- Until the page's JavaScript has loaded, the button can't do anything, so it's kept out of the tab order and hidden from screen readers. The input works as a plain password field in the meantime.

## Accessibility

### Keyboard

| Key | What it does |
| --- | --- |
| <kbd>Tab</kbd> | Moves to the input, then to the button. |
| <kbd>Enter</kbd> or <kbd>Space</kbd> | On the button, shows or hides the password. |

### What the component handles

- The button's name says what pressing it will do: "Show password", then "Hide password". Both can be replaced, for another language. It points at the input with `aria-controls`.
- The eye gets a line through it while the password can be read, so the two states differ by shape as well as by name.
- While the input has keyboard focus, the ring goes around the whole box. The edge of the box uses `--color-border-strong`, at least 3:1 against the page in every theme.
- On a touch screen the button's tap area is 44 by 44 pixels, though it's drawn smaller.

### What you need to handle

- Give it a name. Use a [label](/docs/components/label) whose `htmlFor` matches its `id`, or put it in a [Field](/docs/components/field).
- Let people paste into it. Password managers depend on that.
- Say what the rules for a new password are before it's typed, in a description, not only in an error afterwards.

## Server components

PasswordInput is a client component. It carries `"use client"`, and the build checks that the directive is still there in the published files. You can render it from a server component, as the examples on this page do.

## Do and don't

**Do**

- Use it for every password field, the sign-in form included.
- Set `autoComplete` to `"current-password"` or `"new-password"` to match what the field is for.

**Don't**

- Don't ask for a new password twice to catch typos. Being able to see it does that job.
- Don't block pasting.
