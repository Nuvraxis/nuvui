The editors are a package of their own, `@nuvui/editor`, since editing text needs engines the core doesn't have:

| Component | What it is |
| --- | --- |
| [RichTextEditor](/docs/editor/rich-text-editor) | A box to write formatted text in: bold and italic, headings, lists, quotes, code and links, with a toolbar over it and a small one that comes up over selected text. |
| [CodeEditor](/docs/editor/code-editor) | A box to write code in, colored as a CodeBlock colors it, with search, completion, problems marked in the code, and a file's own history when it's one of a set. |
| [DiffEditor](/docs/editor/diff-editor) | Two texts and what changed between them, side by side or in one column, with each change kept or undone. |

## Install

```sh
pnpm add @nuvui/editor @nuvui/react
```

`@nuvui/react` is a peer dependency: the toolbars are the core's [Toolbar](/docs/components/toolbar), and the box for a link and the search panel are its Popover, Input and Button.

The rich text is edited by [Tiptap](https://tiptap.dev), which is built on ProseMirror, and code by [CodeMirror](https://codemirror.net). Their packages are MIT licensed and are installed with this one. You don't import them yourself, except a CodeMirror extension you choose to give the code editor.

## Two imports

The rich text editor is imported from the package itself, and the code editor and the diff editor from `@nuvui/editor/code`:

```tsx
import { RichTextEditor } from "@nuvui/editor";
import { CodeEditor, DiffEditor } from "@nuvui/editor/code";
```

They're kept apart so that a screen with one doesn't load the other's engine.

## Load the styles

Import the package's stylesheet once, after the core's:

```tsx title="app/layout.tsx"
import "@nuvui/react/styles.css";
import "@nuvui/editor/styles.css";
```

Both files open with the same line naming the cascade layers, so the order you import them in doesn't decide which rule wins. Each editor's styles are also on their own, at `@nuvui/editor/css/rich-text-editor.css`, `code-editor.css` and `diff-editor.css`. With one of those, load `toolbar.css`, `popover.css`, `input.css`, `button.css` and, for the code editors, `select.css`, `toggle.css` and `visually-hidden.css` from `@nuvui/react/css/` as well. The diff editor uses `code-editor.css` too.

Tiptap would otherwise add a few rules of its own in a `style` element it makes at run time. That's turned off, and the rules are in this stylesheet, so a page with a strict content security policy needs no exception for it. CodeMirror draws the code editors with styles it adds as it runs: they take a `nonce`, as the [content security policy](/docs/content-security-policy) page says.

## They're large, so load them when they're needed

The rich text editor is about 120 kB compressed, nearly all of it ProseMirror. The code editor is about 120 kB and the diff editor about 95, nearly all of them CodeMirror, and each language is fetched on its own the first time it's used. Most screens of an app don't have one. Load it with the screen that does:

```tsx
import { lazy, Suspense } from "react";

const RichTextEditor = lazy(() =>
  import("@nuvui/editor").then((module) => ({
    default: module.RichTextEditor,
  })),
);

<Suspense fallback={<Skeleton style={{ blockSize: "12rem" }} />}>
  <RichTextEditor aria-label="Notes" />
</Suspense>;
```

In Next.js, `next/dynamic` does the same. For the code editor, import from `@nuvui/editor/code` in the same way:

```tsx
const CodeEditor = lazy(() =>
  import("@nuvui/editor/code").then((module) => ({
    default: module.CodeEditor,
  })),
);
```

## The rich text editor's value is HTML

`value` is a string of HTML, and `onValueChange` is called with one. It's kept the way any field's value is, shown again on any page without the editor, and sent in an email. Nothing written is the empty string.

Beside the HTML, `onValueChange` gives the same text as data, as plain words, and its counts. [RichTextEditor](/docs/editor/rich-text-editor#the-value) has the details.

## Sanitize before you show it

The editor only writes the elements it knows: paragraphs, headings, lists, quotes, code, links, and the marks for bold and the like. A link's address is the web, email, a phone number or a place on your site, and nothing that runs. What's pasted in goes through the same rules.

That's what the editor writes. What reaches your server is whatever was sent to it, which someone can write by hand. So before HTML from a database is put in a page, pass it through a sanitizer such as [DOMPurify](https://github.com/cure53/DOMPurify) or [sanitize-html](https://github.com/apostrophecms/sanitize-html), on the server, with a list of the elements above. Or show it with the editor itself, [read only](/docs/editor/rich-text-editor#read-only), which reads HTML through the same rules it writes with.

## What the rich text editor leaves out

- **Tiptap extensions of your own.** The engine isn't part of what the component takes or gives, so that it can be changed without changing your code. A mention, a table or an image that uploads isn't built.
- **Images, tables, text color and alignment.**
- **Markdown as the value.** Underline, and anything that's added later, has no markdown to be written as.
- **Several people writing at once.**
- **Uploading.** Nothing is uploaded, so nothing is pasted as a file.

## What the code editors leave out

- **Running the code.** Nothing written is run. The playground block runs it in a sandboxed frame, away from the page.
- **Bundling TypeScript or JSX.** A bundler that runs in the browser, such as esbuild's WebAssembly build, would go between the code and the frame.
- **A language server.** Completion is what each language has by itself. A language server would give its completions and problems through `extensions` and `diagnostics`.
- **Formatting.** `format` is a function you give, so Prettier or anything else is your choice.
- **Several people writing at once.**
