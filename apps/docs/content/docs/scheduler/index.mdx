The scheduler is a package of its own, `@nuvui/scheduler`, since working out days and times in a time zone needs a date library the core doesn't have:

| Component | What it is |
| --- | --- |
| [EventCalendar](/docs/scheduler/event-calendar) | Events in a day, a week, a month or a list, with a header to move through them and a month in a side panel to pick a day from. [Editing events](/docs/scheduler/editing) covers making, changing, moving and deleting them in place, and [Resources](/docs/scheduler/resources) booking them against rooms or people. |

## Install

```sh
pnpm add @nuvui/scheduler @nuvui/date-picker @nuvui/react
```

`@nuvui/react` and `@nuvui/date-picker` are peer dependencies. The calendar is drawn with the core's tokens and buttons, and the month in its side panel is date-picker's `Calendar`.

Days and times are worked out with [date-fns](https://date-fns.org) and `@date-fns/tz`, which are installed with the package, at the same versions as date-picker's, so an app has one copy of each.

## Load the styles

Import the package's stylesheet once, after the core's and date-picker's:

```tsx title="app/layout.tsx"
import "@nuvui/react/styles.css";
import "@nuvui/date-picker/styles.css";
import "@nuvui/scheduler/styles.css";
```

Each file opens with the same line naming the cascade layers, so the order you import them in doesn't decide which rule wins. The calendar's styles are also on their own, at `@nuvui/scheduler/css/event-calendar.css`.

## What it keeps and what you keep

The events are yours when you pass `events`, with `onEventsChange` to hear about each change, or the calendar's when you pass `defaultEvents`. It keeps which view is shown, the day it's on, what the person looking has chosen in its preferences menu, whether its side panel is open, and which resources are hidden or folded. Each of those can be yours instead, through a prop and a callback.

Events and resources can keep your own field names. `eventKeys` and `resourceKeys` say which field is which, and changes come back under the same names. [Resources](/docs/scheduler/resources#your-own-field-names) has the details.

## What's coming

The calendar's views, [editing](/docs/scheduler/editing) and [resources](/docs/scheduler/resources) are in the package. These are planned, in this order, and none is in it yet:

- **Recurring events,** with this one, this and following, or all, when one is changed.
- **A timeline,** with resources as rows and time across.
- **Loading by range,** asking your server only for the days shown.
